Basic Commands

8 commands
docker --version
What it doesPrints the installed Docker CLI version.
Use case: Before deploying or during interviews — confirm Docker is installed and which version you're on. Docker 1.13 = ancient (2017).
docker info
What it doesShows daemon-wide details: storage driver, kernel, runtime, container/image counts, memory.
Use case: First command on any unfamiliar server. Reveals why containers misbehave — wrong storage driver, cgroup version, or resource limits.
docker version
What it doesShows both client AND server (daemon) versions separately.
Use case: When cryptic errors appear, check for client/daemon mismatch — e.g., client 24.x talking to daemon 19.x causes compatibility issues.
docker help
What it doesLists all top-level Docker commands and options.
Use case: When you forget a flag — docker run --help is faster than Googling and matches your exact version.
docker login
What it doesAuthenticates to Docker Hub or another registry.
Use case: Before pushing to a private registry (Docker Hub, ECR, GCR, ACR). Without login, docker push fails with 401.
docker logout
What it doesRemoves stored registry credentials.
Use case: On shared CI/CD machines or a coworker's laptop after finishing. Prevents credential leakage.
docker system info
What it doesAlias for docker info — same output.
Use case: Useful when scripting with the docker system namespace.
docker system df
What it doesShows disk usage broken down by images, containers, volumes, build cache.
Use case: "Why is my disk full?" A single build session can leave 10+ GB of cache. The du command of Docker.
Tip: Add -v for per-item breakdown — see exactly which image is hogging space.

Image Commands

16 commands
docker pull nginx
What it doesDownloads the nginx image (default tag: latest) from Docker Hub.
Use case: Preparing a fresh server. Pull ahead so docker run starts instantly.
docker pull nginx:1.25-alpine
What it doesPulls pinned version + variant: nginx 1.25 on Alpine Linux (~5 MB base vs ~140 MB).
Use case: Production deployments. Never use :latest in prod — silent updates break apps.
docker images
What it doesLists local images with repository, tag, ID, created date, size.
Use case: "Do I already have this image?" before running. Or check total disk usage.
docker image ls -a
What it doesLists ALL images including intermediate layers used in multi-stage builds.
Use case: Inspect build artifacts. Multi-stage builds create intermediate images not shown by default.
docker image ls --filter "dangling=true"
What it doesFinds untagged (<none>:<none>) images left behind after rebuilds.
Use case: After many rebuilds, untagged images eat 20 GB. Common on CI/CD runners.
docker build -t myapp:1.0 .
What it doesBuilds an image from Dockerfile. -t names it; . = build context.
Use case: Every time you change your Dockerfile or code. Turns source into a runnable image.
docker build -t myapp:1.0 -f Dockerfile.dev .
What it doesBuilds using a specific Dockerfile (-f) instead of the default.
Use case: Same project, different environments. Dockerfile.dev = hot reload + debug tools; Dockerfile = lean production image.
docker build --no-cache -t myapp:1.0 .
What it doesRebuilds from scratch — ignores all cached layers.
Use case: "It worked yesterday, now broken." Cached layers hide the real problem.
Warning: Much slower. Only use when debugging cache issues.
docker build --build-arg ENV=prod -t myapp:1.0 .
What it doesPasses a value into an ARG declared in the Dockerfile.
Use case: Same Dockerfile, different outputs — e.g., different API URLs for staging vs production.
docker tag myapp:1.0 username/myapp:1.0
What it doesCreates an alias pointing to the same image ID.
Use case: Before pushing. Registries require namespace/repo:tag format.
docker push username/myapp:1.0
What it doesUploads image layers to Docker Hub or your registry.
Use case: Sharing with teammates, CI/CD, or Kubernetes clusters.
docker rmi myapp:1.0
What it doesRemoves a local image (must not be used by a running container).
Use case: Cleaning up after testing. Frees disk and prevents confusion.
docker rmi -f myapp:1.0
What it doesForce-removes an image even if referenced by a stopped container.
Use case: Emergency cleanup when a container is stuck.
Warning: Can leave orphaned containers. Check docker ps -a after.
docker image prune
What it doesRemoves dangling (untagged) images only.
Use case: Weekly maintenance on dev machines. Very safe.
docker image prune -a
What it doesRemoves all images not used by a running container.
Use case: Reclaiming serious disk space on a build server.
Warning: Next docker run will re-pull images.
docker inspect nginx
What it doesReturns full JSON: config, env, mounts, network, layers.
Use case: Before running an unfamiliar image, see its defaults — CMD, ENTRYPOINT, EXPOSE, WORKDIR. Most useful debugging command.
docker history nginx
What it doesShows each layer of the image and the command that created it.
Use case: "Why is this image 2 GB?" Spot the RUN apt-get install pulling massive packages.

Container Commands

25+ commands
docker run hello-world
What it doesPulls, creates, and runs a test container that exits after printing a message.
Use case: Verifying a fresh Docker install. If this works, Docker's full pipeline works.
docker run -it ubuntu bash
What it does-i = interactive (keep STDIN); -t = TTY. Opens bash inside a fresh Ubuntu.
Use case: Exploring an OS without installing a VM. Great for learning Linux.
docker run -d --name web -p 8080:80 nginx
What it does-d = detached. --name = friendly name. -p host:container = port mapping.
Use case: Standard way to run any web service. Visit localhost:8080 → nginx serves on container port 80.
docker run -d --name db -e MYSQL_ROOT_PASSWORD=secret mysql:8
What it does-e sets environment variables inside the container.
Use case: Local development database. Spin up MySQL in 3 seconds instead of installing it.
docker run -d --name app --restart always myapp:1.0
What it does--restart always = auto-restart on crash or host reboot.
Use case: Production single-container deployments. Essential for services that must stay up.
docker run --rm -it alpine sh
What it does--rm = delete container automatically when it exits.
Use case: Quick debugging or one-off tasks. Test network, DNS, curl from inside a container.
docker run -d -v $(pwd):/app myapp:1.0
What it does-v host:container = bind mount. Edits on host appear inside container instantly.
Use case: Local dev with live reload. Standard for Node/Python workflows.
docker ps
What it doesLists running containers.
Use case: "What's running right now?" First command on any server.
docker ps -a
What it does-a = all containers including stopped/crashed.
Use case: "Why did my container stop?" The crashed one is invisible in plain ps.
docker ps -q
What it does-q = quiet — only container IDs.
Use case: Scripting. docker stop $(docker ps -q) stops everything.
docker ps --filter "status=exited"
What it doesFilters by state: running, paused, exited, etc.
Use case: Finding crashed containers on a busy server — your incident backlog.
docker start web
What it doesStarts a stopped container.
Use case: Bringing a stopped service back online after maintenance.
docker stop web
What it doesGraceful shutdown: SIGTERM → SIGKILL after 10s.
Use case: During maintenance windows. Gives the app time to flush state.
docker restart web
What it doesStops and starts a container.
Use case: Applying a config change (e.g., edited nginx.conf inside).
docker rm web
What it doesRemoves a stopped container.
Use case: Cleanup after testing. Must be stopped first.
docker rm -f web
What it doesForce stop + remove in one command.
Use case: Iterating fast: docker rm -f web && docker run -d --name web ...
docker exec -it web bash
What it doesRuns a NEW command inside an EXISTING running container.
Use case: "SSH into container." Debug app, check env vars, run curl from inside.
Tip: Key difference from docker run: exec doesn't create a new container.
docker logs -f web
What it does-f = follow (like tail -f). Streams stdout/stderr.
Use case: Watching live during deployment. #1 debugging tool.
docker logs --tail 50 web
What it doesLast N lines only.
Use case: Logs are huge. Only recent output matters.
docker logs --since 10m web
What it doesLogs from a specific time window.
Use case: Investigating an incident — "what happened in the 10 minutes before the crash?"
docker cp file.txt web:/tmp/
What it doesCopies files between host ↔ container (both directions).
Use case: Inject configs or extract logs without rebuilding.
docker inspect web
What it doesFull JSON details about a container.
Use case: Deep debugging — check exit codes, mounts, network config.
docker inspect -f '{{.State.Status}}' web
What it doesGo template — extract a single field.
Use case: Health-check scripts in CI. Get just the status, not 500 lines of JSON.
docker stats
What it doesLive CPU, memory, network, disk I/O per container.
Use case: "Is my container using too much RAM?" Spot leaks during load tests.
docker stats --no-stream
What it doesOne snapshot instead of a live stream.
Use case: Scripted monitoring — pipe to a log collector.
docker top web
What it doesShows host-side processes running inside the container.
Use case: Verify no rogue processes or fork bombs.
docker port web
What it doesShows port mappings (e.g., 80/tcp -> 0.0.0.0:8080).
Use case: Forgot the mapping? Tell a teammate the URL.
docker diff web
What it doesLists files changed vs the original image (A/C/D).
Use case: "What did this container write?" Catches runaway logs or unexpected files.

Volume Commands

8 commands
docker volume create mydata
What it doesCreates a named volume managed by Docker.
Use case: Persistent storage for databases. Pre-create so multiple containers can share it.
docker volume ls
What it doesLists all volumes.
Use case: "Where did my data go?" After container deletion, named volumes remain.
docker volume inspect mydata
What it doesShows mount point, driver, labels.
Use case: Find where data lives on the host for backups.
docker volume rm mydata
What it doesDeletes a volume (must be unused).
Use case: Final cleanup after a project ends.
docker volume prune
What it doesRemoves UNUSED volumes.
Use case: Reclaiming space after removing containers.
Warning: Data loss. Check docker volume ls first.
docker run -d -v mydata:/var/lib/mysql mysql:8
What it doesMounts named volume into container path.
Use case: Running any database. Without this, data dies with the container.
docker run -d -v $(pwd)/html:/usr/share/nginx/html nginx
What it doesBind mount: host path → container path.
Use case: Serving a static site from your laptop. Edit HTML, refresh browser.
docker run -d --mount source=mydata,target=/data nginx
What it doesModern explicit syntax for mounting.
Use case: Production deployments. Preferred over -v in Compose and Kubernetes manifests.

Network Commands

9 commands
docker network ls
What it doesLists networks (default: bridge, host, none).
Use case: Before connecting containers, see what's available.
docker network create mynet
What it doesCreates a user-defined bridge network.
Use case: Microservices setup. Containers on the same network resolve each other by name (DNS).
docker network inspect mynet
What it doesShows connected containers, subnet, gateway.
Use case: "Why can't container A reach container B?" Shows exactly who's connected.
docker network connect mynet web
What it doesAttaches a running container to a network.
Use case: Expanding an app without restarting containers.
docker network disconnect mynet web
What it doesDetaches a container from a network.
Use case: Isolating a container for security testing.
docker network rm mynet
What it doesDeletes a network (must have no containers).
Use case: Cleaning up after a project.
docker network prune
What it doesRemoves unused networks.
Use case: Cleanup after Compose projects are down.
docker run -d --network mynet --name api nginx
What it doesRuns container on a user-defined network.
Use case: Microservices — other containers reach this one at http://api:80.
Why user-defined networks matter: Containers get automatic DNS. On the default bridge, you can only reach them by IP.

Docker Compose

14 commands
docker compose up
What it doesCreates and starts all services (foreground, you see logs).
Use case: Starting a multi-service app for development while watching logs.
docker compose up -d
What it does-d = detached (background).
Use case: You want your terminal back for other work.
docker compose up --build
What it doesRebuilds images before starting.
Use case: After editing code or Dockerfile — rebuild + restart in one command.
docker compose down
What it doesStops and removes containers + networks. Volumes stay.
Use case: End of day cleanup. Data is safe.
docker compose down -v
What it doesAlso removes volumes.
Use case: Reset to a clean slate — fresh database.
Warning: Database wiped. Only use when you mean it.
docker compose ps
What it doesLists compose project containers.
Use case: "What services are up?" at a glance.
docker compose logs -f
What it doesFollows logs of ALL services, prefixed by service name.
Use case: Watching all services at once during a bug hunt.
docker compose logs web
What it doesLogs for one service.
Use case: Focused debugging — cleaner output.
docker compose exec web bash
What it doesShell into one service.
Use case: Debug a component while others keep running.
docker compose restart web
What it doesRestart one service.
Use case: Apply config changes without touching other services.
docker compose stop
What it doesStops all services without removing.
Use case: Pause a stack for lunch or RAM savings. Resume with start.
docker compose start
What it doesRestarts stopped services.
Use case: After a stop — instant resume with preserved state.
docker compose build
What it doesBuilds images only.
Use case: Pre-building in CI so up is fast.
docker compose config
What it doesValidates and prints the resolved YAML.
Use case: Catch syntax errors before running. See env-var substitution results.

Sample docker-compose.yml

docker-compose.yml 
version: '3.8'
services:
  web:
    build: .
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html
    depends_on:
      - db
  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: secret
    volumes:
      - dbdata:/var/lib/mysql
volumes:
  dbdata:

Dockerfile

14 instructions

Node.js App

Dockerfile (Node) 
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "index.js"]

Python App

Dockerfile (Python) 
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 5000
CMD ["python", "app.py"]

Multi-Stage Build

Dockerfile (multi-stage) 
# Build stage
FROM node:20-alpine AS builder
WORKDIR /app
COPY . .
RUN npm install && npm run build

# Runtime stage
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Instruction Reference

InstructionPurposeUse Case
FROMBase imageChoose your base: node:20-alpine for small Node apps
WORKDIRSet working directoryAvoid messy absolute paths in COPY/RUN/CMD
COPYCopy files from hostCopy package.json first, then source — for layer caching
ADDCopy + extract URLs/tarballsRarely needed; prefer COPY unless extracting tar
RUNExecute at build timeInstall packages; combine with cache cleanup in one layer
CMDDefault runtime commandDefault args — overridable by docker run arguments
ENTRYPOINTFixed executablePair with CMD for CLI tools where args vary
EXPOSEDocument portCompose and inspect use this to auto-map ports
ENVEnvironment variableSet defaults like NODE_ENV=production
ARGBuild-time variablePass with --build-arg for different build variants
VOLUMEMount pointFor images that always need persistence
USERRun as userSecurity — run as non-root to limit exploit damage
LABELMetadataTrack maintainer, version, description
HEALTHCHECKContainer health testEnables auto-restart on unhealthy state

Cleanup Commands

11 commands
docker container prune
What it removesAll stopped containers.
Use case: Daily CI runner cleanup. Stopped containers pile up; this clears them safely.
docker image prune
What it removesDangling (untagged) images only.
Use case: Weekly dev maintenance — very safe.
docker image prune -a
What it removesAll images not used by a container.
Use case: Reclaiming disk space fast.
Warning: Next docker run re-pulls images.
docker volume prune
What it removesVolumes not used by any container.
Use case: After removing a database container.
Warning: Data loss. Check docker volume ls first.
docker network prune
What it removesUnused networks.
Use case: After Compose projects are down. Removes orphaned networks.
docker system prune
What it removesStopped containers + dangling images + unused networks + build cache.
Use case: The safe default cleanup. Weekly habit.
docker system prune -a
What it removesEverything unused — including all images not in use.
Use case: Aggressive cleanup when disk is critical.
docker system prune -a --volumes
What it removesNuclear option — everything including volumes.
Use case: Before decommissioning a machine or a full factory reset.
Warning: Data will be lost permanently.
docker stop $(docker ps -aq)
What it doesCommand substitution: stops ALL containers.
Use case: "Stop everything now" before shutdown, or a fresh start.
docker rm $(docker ps -aq)
What it doesRemoves all stopped containers.
Use case: Full cleanup after stopping everything.
docker rmi $(docker images -q)
What it doesRemoves all images.
Use case: Wiping all images for a clean slate.

Troubleshooting

12 scenarios

1. Container Won't Start

docker logs container_name
What it doesReads stdout/stderr captured by Docker.
Use case: The #1 place to find the crash reason. Always first.
docker inspect container_name | grep -i error
What it doesSearches the JSON for error fields.
Use case: When logs are empty (process never started).
docker events
What it doesLive stream of daemon events (start, die, kill, oom).
Use case: Watch in one terminal while reproducing the bug in another — see exact timing.

2. Port Already in Use

docker ps --format '{{.Names}} {{.Ports}}'
What it doesCustom format — just names and ports.
Use case: Find which container holds port 8080.
lsof -i :8080
What it doesHost-level tool — shows the process owning a port.
Use case: Something outside Docker (like host nginx) holds the port.

3. Out of Disk Space

docker system df -v
What it doesVerbose, per-item breakdown.
Use case: The definitive space audit. Find the 15 GB image.

4. Container Exits Immediately

docker inspect container_name --format '{{.State.ExitCode}}'
What it doesExtracts just the exit code.
Use case: Decode the failure — 0=clean, 1=app error, 137=SIGKILL (OOM), 139=segfault, 143=SIGTERM.
docker run -it --entrypoint sh image_name
What it doesOverrides the ENTRYPOINT to get a shell.
Use case: Bypass a broken entrypoint to explore what's wrong inside the image.

5. Network Issues

docker exec -it container_name ping google.com
What it doesTests connectivity from inside the container.
Use case: The only place that matters for DNS/network debugging — from inside.
docker exec -it container_name nslookup other_container
What it doesTests Docker's internal DNS resolution.
Use case: "Why can't A reach B?" — verify name resolution.

6. Permission Denied (Linux)

sudo usermod -aG docker $USER
What it doesAdds your user to the docker group.
Use case: Run Docker without sudo. Standard first-day fix.
Then run: newgrp docker — refreshes group membership in the current shell.

7. Image Build Failures

docker build --progress=plain -t myapp .
What it doesShows raw, non-collapsed build output.
Use case: See exactly which RUN failed and its full error message.

8. Performance / Resource Issues

docker update --memory 512m --cpus 1.0 container_name
What it doesLive-adjust limits on a running container.
Use case: No restart needed — apply new limits on the fly.

9. Docker Daemon Issues

sudo systemctl restart docker
What it doesStandard systemd restart.
Use case: Fix a hung daemon.
sudo journalctl -u docker.service -n 100
What it doesLast 100 daemon log lines.
Use case: Where startup failures are explained.

10. Container Health Check

docker inspect --format='{{.State.Health.Status}}' container_name
What it doesReturns healthy, unhealthy, or starting.
Use case: Automation-ready health check. Only works if Dockerfile defined HEALTHCHECK.

11. Dive into Filesystem

docker diff container_name
What it doesShows A (added), C (changed), D (deleted) files vs the image.
Use case: See what a container modified — catch runaway logs or unexpected writes.

12. Kernel / Runtime Diagnostics

dmesg | grep -i docker
What it doesKernel-level messages related to Docker.
Use case: OOM kills, cgroup errors, overlayfs issues.
